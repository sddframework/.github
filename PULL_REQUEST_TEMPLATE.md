## What changes and why

Describe the problem and the resulting behavior. Link a related issue or
discussion when one exists. Follow the
[contribution guide](https://github.com/sddframework/.github/blob/main/CONTRIBUTING.md).

## Verification

State what you checked, how you checked it, and any remaining limits. For a
documentation change, a careful review may be sufficient. For a behavior change,
include the relevant reproduction or checks; distinguish local checks from
hosted or production evidence.

For a framework behavior change, identify the acceptance criteria and explain
the test changes. Include the observed baseline and final acceptance results,
and any unverified, flaky, or blocked checks that remain.

## Contributor checklist

- [ ] The change has a focused scope and follows the contribution guide.
- [ ] Documentation and examples match the current project status.
- [ ] I have the right to submit the contribution under this repository's terms.
